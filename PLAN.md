# Port plan: bibtex-tidy

Rust port of [FlamingTempura/bibtex-tidy](https://github.com/FlamingTempura/bibtex-tidy) — a BibTeX cleaner/formatter CLI.

## Progress snapshot

- Upstream pin: <https://github.com/FlamingTempura/bibtex-tidy.git> @ `e9795a784cc7dbdca0c13cb4047606683d8fc018` (v1.15.1-4-ge9795a7; original `--version` = `v1.15.1`)
- Sync target: none
- Oracle binary: `upstream/bin/bibtex-tidy` (committed build artifact at the pin commit; sha256 `ccd2cb1233d3c127b408f3b2d19ab30e5535eb1e933ad43a6437af61c5697373`; run with `node` v24.22.2; reports `v1.15.1`)
- Working end-to-end: stdin→stdout tidy (default path), file modify/output/backup, `--version`/`--help`/unknown-args, `--quiet`, `--v2`, deprecated-stdio notice, `--omit`, plus the option-gated transforms XF-01/03/07/08/11/13/14/15/16/17/19/20/21/22/25 (incl. generateKeys + mergeEntries + the name parser) — all matching the original on the CLI-surface + spec corpus
- Current stage: S6 Ship (complete — initial port delivered)
- Next: S7 — Upstream sync (recurring maintenance, not part of the initial definition of done)
- Blockers: none
- CI/CD: `release.yml` (authoritative) runs fmt/clippy/audit + the G-PARITY gate in its lint job, and a per-target test+build matrix on all six §10.1 targets; pushes to `main` publish the moving `nightly` release, `v*` tags publish that tag. `main` is branch-protected (require PR + the Release checks, no direct pushes).

### Parity gating note

- The parity corpus (`tests/parity/cases/*.json`, **131 fixtures** = 40 CLI-surface + 91 converted from `upstream/test/spec/*.spec.yaml`) is **fully green** for the implemented path: `cargo test --test parity_check -- --ignored` → 131/131. The 91 spec cases are generated by `define_spec_cases.py` (camelCase option → CLI flag) and captured from the original via `capture.py`; the full spec corpus now lands green (no unported transforms remain). The 12 CLI cases added in S5 cover the JS-truthiness (`--align`/`--wrap`/`--max-authors` bare/`0`/NaN) and generate-keys fatal/array semantics fixes. The 3 generate-keys fatal-crash cases use the `exit_stdout_files` policy: stdout (empty) and exit code (1) match, but the original's Node.js stack-trace wording is non-functional per INV-PARITY.
- The Rust check test `tests/parity_check.rs` remains `#[ignore]`d so `cargo test` (G-TEST) stays green by default; G-PARITY runs explicitly via `cargo test --test parity_check -- --ignored`. It becomes a required CI check in S4 once the full spec corpus lands green.
- S1 self-check (`python3 tests/parity/capture.py verify`) replays the original against the stored fixtures: **106/106 green**, confirming fixtures are deterministic and normalization is sound.
- File-mode cases set `PRE_COMMIT=1` (the original's own switch for "no stdin"); without it a piped stdin makes the parser treat trailing filenames as option values (see `define_cli_cases.py`).
- **Fixture re-authoring (INV-ORACLE-logged):** `help-long`, `help-short`, `unknown-single`, `unknown-multiple` were originally captured with `match: full` on the help body / unknown-option error wording — both non-functional per INV-PARITY. They are re-authored to `match: exit_only` (assert exit code only) so they don't pin our own help/error wording to the original's. No captured *functional* behavior (exit code) was weakened; the `--version`/exit/stdin/file cases are untouched.

## Scope decisions

- **In scope (§2):** the terminal CLI (`upstream/src/cli/cli.ts` + the tidy core it drives): arg parsing, option normalization, the parse → transform → format pipeline, stdin/file I/O, `--modify`/`--output`/backup, exit codes, logging.
- **Out of scope (not ported, not counted as gaps):** the Svelte web UI (`upstream/src/ui/**`), the browser/editor integrations, the npm library surface (`bibtex-tidy.d.ts`, `index.ts` re-exports as a published SDK), the Docker image (`upstream/docker`), and the Playwright visual-regression tests. Delivered as a `[[bin]]` only — no `lib.rs`.
